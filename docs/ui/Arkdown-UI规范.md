# Arkdown UI 规范

## 业务弹窗

- 主标题与主要提示使用 `17px`；灰色 description 使用 `13px`，保持弱提示层级。
- Primary 按钮固定使用偏好设置确认按钮配色，浅色和深色模式一致，不跟随主题色：

  | 状态 | 颜色 |
  | --- | --- |
  | Base | `#4183C4` |
  | Hover | `#3677B7` |
  | Pressed | `#2F699F` |

- 弹窗 tone 或危险语义不得覆盖 primary 的固定配色；仅明确标记为非 primary 的危险动作使用 danger 样式。
- 关闭 AI 确认的“停止任务并关闭”和 OCR Medium 删除确认的“是”均为 primary，使用上述固定蓝色；文档转换组件删除仍保留非 primary 的 danger 样式。
- 通用文字输入（含图片替代文本、代码语言）与便签名称输入复用规范字段：13 CSS px 字号、32 CSS px 高度、8 CSS px 圆角，基础边框与深浅色使用共享弹窗 token。150% 下分别约为 19.5、48、12 屏幕物理像素。
- 所有业务弹窗内的输入框聚焦时不新增彩色描边、内外光圈或边框颜色变化；保留原有基础边框和校验错误边框，以输入光标表示文字输入焦点。高对比度下字段统一使用系统 `CanvasText` 边框，防止 Chromium 自动将聚焦边框换为 `Highlight`。此规则仅作用于弹窗字段，不改变编辑器、非模态页面输入或按钮（含下拉选择按钮）的键盘焦点反馈。
- 弹窗操作按钮的键盘焦点反馈必须绘制在按钮内部，不使用正值 `outline-offset` 外扩描边，避免自动聚焦时出现主题色外圈或改变视觉占位。普通按钮使用固定重点色 `#4183C4` 的边框与内描边；primary 按钮保持固定蓝色底，并使用白色内描边提供清晰对比。焦点反馈不得跟随彩色主题变化。Windows forced-colors/高对比度模式下，使用系统 `Highlight` 色的 `2px` outline 和 `-3px` offset 将焦点线收进按钮内部，并取消可能被系统抑制的 `box-shadow`。
- 三按钮保存确认从左到右、从前到后的键盘 Tab 顺序均为“保存、不保存、取消”。“保存”是 primary；“不保存”和“取消”是普通按钮，不使用 danger 样式。

尺寸以 CSS px 记录；在 Windows 150% 验收基准下，`17px` 和 `13px` 分别约为 25.5 与 19.5 屏幕物理像素。

## 未配置大模型面板引导（主题色例外）

- AI 对话、翻译侧栏和翻译 popover 复用 ModelConfigurationNotice；标题“尚未配置大模型”，说明“请先配置大模型，再使用此功能。”，操作“前往配置”“暂不”。
- 标题/正文 14 CSS px，主/次按钮 13/12 CSS px，按钮高 32 CSS px，主按钮至少宽 117 CSS px；150% 下分别为 21、19.5/18、48、175.5 屏幕物理像素。
- 用户指定的主题色例外只限此组件：主按钮 base 为主题色，hover 为主题色 88% 不透明度，pressed 为 76%；三处共用状态规则，不修改业务弹窗 primary 固定蓝色规则。
- 侧栏共用 53 CSS px 页脚预留区域（翻译页脚 32px 控件 + 20px 内边距 + 1px 边框），引导在其上方同等可用区域居中；翻译历史继续隐藏 live guide。
