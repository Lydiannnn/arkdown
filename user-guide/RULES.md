# Arkdown 使用说明书维护规则

这份规则书只用于维护说明书源码，不复制到普通用户的免安装版目录。

## 内容真实性

- 只描述当前发布版本中已经通过测试的行为。
- 新功能必须先进入产品、通过验证，再进入说明书。
- 暂未支持的功能只能写成限制，不得写成操作入口。
- 面向普通用户表达；内部模块、IPC、修订哈希等术语不得进入正文。
- 操作名称、按钮文字和状态文字必须与当前软件界面一致。
- 支持格式必须以 `src/shared/document-types.ts` 的唯一文档类型注册表为准，不得另写一套推测清单。
- 保存说明必须明确区分 `temp` 临时草稿与用户手动写回的原文件。
- 右键菜单说明必须按“文本与结构、链接、图片、表格、源码模式、工作区条目”分清上下文，不得把所有命令写成任何位置都可用。
- 代码块和任务列表使用文本与结构菜单；引用、代码块和列表按钮的高亮及再次点击取消行为必须与软件保持一致。
- 引用资源必须描述为“保留原位置并记录绝对路径”；图片另存为或复制到只创建副本，不得写成移动、重命名、删除或覆盖原资源。
- 浏览器搜索必须说明为用户主动操作，并明确 Arkdown 不能读取浏览器内部的默认搜索引擎。

## 页面与链接

- 根入口固定为 `使用说明书.html`。
- 子页面固定放在 `使用说明书/`，所有资源使用相对路径。
- 每个小节 ID 在全站唯一且稳定；改名时同步搜索索引和交叉链接。
- 新页面必须加入左侧分组、上一页/下一页和完整性测试。
- 页面顺序以 `content.ts` 中的 `GUIDE_PAGES` 为唯一来源。

## 截图

- 只使用最终打包程序和清理过隐私的示例工作区。
- 禁止占位图、模拟界面、用户真实路径、账号或私人文档。
- 截图文件使用小写 ASCII 与连字符命名，PNG 格式，不拉伸。
- 软件界面变化后必须重拍受影响截图并检查图注。
- 截图只用于解释真实操作，不能展示当前版本不存在的控件。

## 便签功能

- 活跃便签最多 35 个；归档便签不计入 35 个上限。
- 从外部 Markdown 导入便签时，只复制引用的本地资源到便签资源目录；不得修改源文档或源资源。
- 从正文建立便签时应说明为创建独立副本，不得暗示会移动或改写原文档。
- “释放到桌面”表示打开独立便签窗口；“从桌面回收”只关闭桌面展示，不删除也不归档。
- Pin 只表示便签窗口始终置顶，不得描述为固定内容或锁定编辑。
- 独立样式不受全局预设修改影响；颜色和底纹仍可任意组合。
- 搜索活跃便签与搜索归档便签必须分开说明，活跃搜索不包含归档内容。
- 开机启动说明必须保留免安装版移动程序文件夹后路径失效的警告。

## 搜索索引

- 索引从 `content.ts` 生成，不手工维护第二份内容。
- 每节提供标题、摘要和能覆盖普通用户说法的关键词。
- 搜索不得访问用户工作区或发起网络请求。
- 新增或改写章节后必须验证常见中文关键词仍能找到正确结果。

## 版本与打包

- 修改软件版本或功能范围时同步版本号、更新时间、FAQ 和限制列表。
- `npm run package` 必须自动构建并复制说明书到程序根目录。
- 维护规则本身不复制到普通用户的免安装目录。
- 入口文件必须与 `Arkdown.exe` 同级，资源目录名固定为 `使用说明书`。

## 发布前检查

- 运行内容、模板、交互、样式、截图和打包测试。
- 在 `file://` 下测试首页、所有子页、搜索、目录、抽屉和图片放大。
- 使用桌面与 390×844 视口和参考页并排检查。
- 检查全部文案是否与当前 Arkdown 功能一致。
- 核对启动空白状态、拖入新窗口、本地源路径引用、对象右键菜单、PDF Ctrl+点击、临时草稿和异常恢复流程。
- 检查说明书中没有个人路径、临时文件、远程资源或失效链接。
